# パラメーター変更方針

> **旧仕様の記録**: バランス測定基盤（`tools/balance/`）と実測結果の文書は役目を終えたため削除しました。
> この文書は当時の設計方針を残すための記録で、現行の仕様とは一致しません。
> 文中の `tools/balance/` や `*-results.md`、`experiment-log.md` への参照は、すでに存在しないファイルを指します。

## 現段階の権限

2026年8月13日、ゲーム本体へ妥当と判断した概略調整を反映する権限が承認されました。測定結果に基づき、既存要素の数値、敵数、能力、既存特性の組合せを調整できます。最終的な手触りと微調整は人間が行います。

自動採用、自動コミット、自動プッシュは行いません。変更理由、測定条件、変更前後、加入後戦力、元に戻す方法を記録し、ゲーム本体へ反映した値も人間が見直せる暫定値として扱います。

## 比較的測定しやすい候補

人間が探索範囲を承認した後、1群ずつ候補生成できる項目です。

| 項目 | 主な定義・処理 | 直接影響 | 注意点 |
| --- | --- | --- | --- |
| 襲撃者のHP・攻撃・能力 | js/data/raidData.js、js/raid.js | 戦闘ターン、被害、勝敗 | 敵数や特殊能力と同時に変えない |
| 襲撃間隔の数値 | js/raidSchedule.js | 年間襲撃回数 | 回復期間と長期経済へ波及する |
| 建築費 | js/buildings.js | 建設可能時期 | 村規模と敵テーブルを早める |
| 奇跡の消費魔素 | js/miracles.js | 使用回数 | 回復、交換、人口、戦力へ波及する |
| 神威獲得量 | js/divineMight.js、各獲得元 | 奇跡解放時期 | 異端審問と黄金像を前倒しする |
| 黄金像の費用 | js/buildings.js | 黙示録開始時期と残備蓄 | 到達時期と攻略難易度を同時に変える |

自動候補の初期変更幅は、原則として現行値の±10%以内とします。整数、確率、最低値などの境界は個別に丸め方を決めます。2026年8月13日の承認により、上位襲撃者については敵数・身体能力・精神特性の広域探索と概略調整に限り、この範囲を超えて比較できます。

## 連動調整が必要な候補

次は単一の数値に見えても複数システムを動かすため、候補生成前に依存関係と測定シナリオを指定します。

### 建築費

建築費
→ 建設時期
→ 村規模
→ 村称号
→ 解放建物
→ 防衛人数
→ 襲撃候補
→ 異端審問
→ 黄金像
→ 黙示録到達時期

建築費を調整するときは、通常進行の生存率だけでなく、規模到達月、襲撃段階、黄金像到達月も同時に測ります。

### 敵攻撃力

敵攻撃力
→ 被ダメージ
→ 負傷・重体・死亡
→ 療養人数
→ 翌月以降の生産低下
→ 食料・資源収支
→ 修繕能力
→ 次回襲撃への準備
→ 長期的な詰み率

単発勝率だけを合わせる変更は禁止します。襲撃後復旧と通常進行を必ず併測します。

### 襲撃者の身体能力と加入後戦力

上位襲撃者と黙示録随伴兵は、交換の奇跡・強と松かさの杖によって肉体を比較的容易に村側へ移せます。また、完全成功後に捕虜となり、懐柔または誘惑を経て本人が加入する経路もあります。

このため、敵としての強さだけを目的に身体能力を上げません。襲撃者の能力を変更するときは、次を別々に測ります。

- 交換で村人へ渡るHP、筋力、耐久、器用、魔力、魅力、肉体特性。
- 捕虜本人が加入した場合の、精神能力と精神特性を含む実効能力。
- 通常に育成した同時期の村人および既存の強い捕虜候補との比較。
- 捕虜の取得率、収容上限、懐柔・誘惑係数を含む入手難度。

敵の脅威を上げる必要がある場合は、身体能力の単純な増加より、既存の精神特性「狂信」「秘蹟：剣」「秘蹟：盾」「歴戦」「戦慣れ」と、敵数・役割構成の組合せを先に検討します。ただし、これらは肉体交換では移らなくても、捕虜本人の加入時には残るため、無制限な敵専用補正として扱いません。

身体能力を下げて精神特性で敵時の実効値を補う候補では、身体交換後と本人加入後の両方が強すぎないことを採用条件とします。

### 奇跡消費

奇跡消費
→ 奇跡使用頻度
→ 負傷回復
→ 肉体交換
→ 能力構成
→ 妊娠・人口構成
→ 捕虜加入の相対価値
→ 襲撃戦力
→ 魔素の希少性

黙示録だけを見て消費量を下げず、通常進行、交換、旅人、回復への影響を確認します。

### 神威と村規模

神威獲得量・閾値
→ 奇跡解放
→ 異端審問条件
→ 黄金像解放
→ 魔素の使い道
→ 黙示録準備期間

村規模値・称号閾値
→ 建物解放
→ 防衛枠
→ 訪問者数
→ 襲撃候補
→ 黄金像条件

神威と村規模は、黄金像到達時期の別々の律速要因として測定し、原則として同じ実験で同時変更しません。

## 人間承認が必要な項目

次は数値候補を機械的に比較できても、プレイ体験や仕様の意味が変わるため、人間が候補と影響を確認してから変更します。

- 襲撃の完全成功・部分成功・失敗条件。
- 襲撃失敗時の資源、建物、捕虜、死亡ペナルティー。
- 襲撃回避に必要な資源と、回避可能な敵。
- 防衛人数の上限と建物による増加。
- 神威レベル、村規模称号、建物解放の閾値。
- 黄金像の解放条件と黙示録開始条件。
- 奇跡の効果量、対象、交換可能範囲。
- 秘宝の効果、入手率、持込条件。
- 捕虜の加入条件と加入後能力。

## 自動変更しない項目

次は自動調整対象にしません。変更する場合は、別の設計依頼と明示的な承認を必要とします。

- 戦闘式、死亡、負傷、重体の意味。
- 第6・第7災厄の敵全滅条件を含む黙示録構造。
- 黄金像破壊、中断、再挑戦、仮エンディングの意味。
- Village、Villager、保存JSONのフィールド構造。
- 世界観、会話、人物設定、性別、種族、年齢の意味。
- UI操作や表示を、測定結果だけを理由に削除する変更。
- 不具合をバランス要素として固定する変更。

## 変更単位

- 1実験では原則1つの数値群だけを変える。
- 敵HPと攻撃力など複数値を組にする場合は、組にする理由を experiment-log.md へ書く。
- 共通の乱数種で現行値と候補を比較する。
- 目標値を満たしても、別指標を悪化させた候補は自動採用しない。
- 変更前に対象ファイル、参照箇所、保存互換性、UI表示、用語集への影響を確認する。
- JavaScript変更時は AGENTS.md と CODE_REVIEW.md の検証規則に従う。

## 候補報告に必要な内容

- 変更した値とファイル。
- 変更理由と期待した因果関係。
- 使用したシナリオ、プレイヤーモデル、乱数種、試行数。
- 変更前後の全主要指標。
- 改善した指標と悪化した指標。
- 境界値、外れ値、測定エラー。
- 襲撃者を変更した場合は、交換可能な肉体能力と、本人加入時の精神特性込み能力。
- 採用、却下、保留の提案。
- 元に戻す方法。

報告は人間の判断材料であり、正式採用の命令ではありません。
